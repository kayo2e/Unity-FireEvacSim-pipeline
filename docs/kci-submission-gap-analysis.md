# KCI 저널 게재를 위한 보완 사항 분석

특정 학회지를 아직 정하지 않은 상태이므로, 일반적인 KCI 등재 이공계 학술지(소방·안전·
건축·AI 응용 계열)의 심사 관행을 기준으로 작성했다. 학회를 확정하면 해당 저널의 분량·
서식·통계 검정 요구 수준을 다시 맞춰야 한다.

## 결론 먼저: "raw 데이터셋 부재"는 최우선 문제가 아니다

화재 대피 시뮬레이션 분야는 **실제 화재 상황에서 실험 데이터를 수집하는 것 자체가 윤리적·
현실적으로 불가능**하기 때문에, 순수 시뮬레이션 논문이 KCI 등재지에 실리는 사례는 흔하다
(참고문헌 [1] Lee et al., *Fire Sci. Eng.* 2025도 시뮬레이션 기반이다). 심사자들도 이
전제를 이해한다.

대신 raw 데이터가 없을 때 요구되는 것은 **군중 행동 모델 자체의 근거**이며, 이 프로젝트는
이미 Fruin(1971)·Helbing(2000)이라는 실측 데이터로 검증된 문헌 모델을 인용해 군중 물리를
구현하고 있다 — 이게 "raw 데이터가 없어도 되는" 표준적인 우회로다. 게다가 "raw 데이터가
아예 없다"는 전제도 정확하지 않다 — **화재 데이터는 없지만, 군중 물리 모델 자체를 검증할
실측 보행자 데이터는 공개돼 있다**(Pedestrian Dynamics Data Archive 등, 상세는
[`docs/simulation-parameter-justification.md`](simulation-parameter-justification.md)
참고). 즉 이 축은 생각보다 훨씬 더 방어 가능하고, 남은 것(아래 "가장 시급한 보완" 1번)이
실제 리스크다.

**더 실제로 심사에서 걸릴 가능성이 높은 문제는 아래 항목들이며, raw 데이터 수집보다 비용
대비 효과가 훨씬 크다.**

## 가장 시급한 보완 (개고 없이 통계·문헌만 보강해도 되는 것들)

### 1. 시뮬레이션 모델 자체의 타당성 검증 근거가 약하다

Helbing/Fruin 모델을 "인용"하는 것과, 그 모델의 파라미터를 **이 프로젝트의 맵·군중
밀도 조건에 맞게 왜 그 값으로 설정했는지 정당화**하는 것은 다르다. 현재 `env_core.py`의
구체적 파라미터(공황 확산 계수, 밀도-속도 감소 곡선 등)가 원 논문 수치와 어떻게
연결되는지 문서화된 곳이 없다. 최소한 부록 표로 "파라미터 → 출처 문헌 값 → 채택 이유"를
정리하면, raw 데이터 없이도 검증 가능성을 크게 높일 수 있다.

### 2. 평균±표준편차만 있고 통계적 유의성 검정이 없다

표 3의 PPO vs A* 비교(30 에피소드)는 mean±SD만 보고한다. KCI 심사자들은 두 방법을
비교할 때 **paired t-test 또는 Mann-Whitney U test**(생존율처럼 정규성이 깨지기 쉬운
지표는 비모수 검정 권장) 같은 유의성 검정을 기본으로 기대하는 경우가 많다. 이미 30
에피소드 데이터가 있으므로 새 실험 없이 `scipy.stats`로 즉시 추가 가능 — 투자 대비
효과가 가장 큰 항목이다.

### 3. 관련 연구(Related Work) 섹션이 사실상 없다

참고문헌이 PPO 원 논문 [1], A* 변형 논문 [2], 군중 모델 문헌 2건뿐이다. **다른 DRL 기반
대피 유도 연구들과 이 프로젝트가 어떻게 다른지** 비교하는 절이 없으면, "이게 왜
새로운가"라는 심사자의 첫 질문에 답할 근거가 없다. 최소 5~10편의 DRL/강화학습 기반
대피·군중 제어 선행연구를 찾아 표로 비교(관측 공간, 액션 공간, 검증 방법, 우리와의 차별점)
하는 절을 추가해야 한다.

### 4. 단일 건물·단일 평면도로만 검증됐다

모든 실험이 "실제 상상관 2층" 평면도 하나에서 나온 결과다. 심사자가 반드시 묻는 질문:
"다른 건물 구조에서도 통하는가?" 최소 1~2개의 추가 평면도(단순 격자형, 복도가 여러 개인
구조 등 구조적으로 다른 레이아웃)에서 같은 정책이 어떻게 일반화되는지 보여줘야 외적
타당성(external validity) 문제를 방어할 수 있다. Stage 1 파이프라인이 이미 임의의
평면도 이미지 → 그리드 변환을 지원하므로, 새 이미지 몇 장만 있으면 추가 실험 자체는
어렵지 않다.

## 코드/재현성 이슈 (독립적으로 발견, 이번 세션에서 수정)

### 5. RecurrentPPO / JointPPO / AutoregressivePPO — 학습된 결과는 있는데 코드가 없다

`stage2/model/`, `stage2/logs/`에 세 변형 알고리즘의 체크포인트·로그가 남아 있지만,
해당 소스 코드(`env_joint.py`, `train_joint.py`, `autoregressive_ppo/` 패키지 등)는
"미사용 코드 정리" 커밋에서 삭제됐다(현재 `main` HEAD 기준 미존재, git 히스토리에는
남아 있음 — 필요시 `git show <hash>:stage2/env_joint.py` 등으로 복구 가능). 현재
README에는 이미 이 세 변형이 언급되지 않도록 정리되어 있어 문서-코드 불일치는 없지만,
**논문에 이 세 변형의 비교 결과를 포함하고 싶다면 코드를 히스토리에서 복구해야
재현 가능**하다. 포함하지 않을 거라면 orphan 상태인 `model/`, `logs/` 하위 디렉터리를
정리(삭제 또는 `archive/` 표기)하는 게 재현성 심사에 유리하다 — 코드 없는 결과물이
저장소에 남아 있으면 "이 숫자는 어디서 나온 거냐"는 질문을 받는다.

### 6. 코드/데이터 공개 방식이 논문 표준에 맞지 않는다

현재는 GitHub 저장소만 있고 버전 고정(release tag 등), DOI 아카이브(Zenodo 등),
라이선스 파일이 없다. 대부분의 KCI 공학 저널이 요구하는 "코드/데이터 가용성 명시"
문구를 채우려면: (a) 논문 제출 시점의 커밋을 release/tag로 고정, (b) Zenodo 등으로
DOI 발급, (c) LICENSE 파일 추가가 필요하다. 이번 세션에서 커밋 히스토리는 이미
정리했으니 이 작업의 전제 조건은 충족된 상태다.

## 정리하면 — 우선순위

| 우선순위 | 항목 | 소요 | 상태 |
|---|---|---|---|
| 1 | 통계적 유의성 검정 추가 (표 3) | 낮음 | **S4 완료**(seed 페어링 + paired t-test/Wilcoxon) — 나머지 시나리오는 동일 방식으로 재측정 필요 |
| 2 | 관련 연구 절 작성 | 중간 | **완료** — README `## 관련 연구` 참고 |
| 3 | 시뮬레이션 파라미터 근거표 (Fruin/Helbing 대응) | 낮음 | **완료** — [`docs/simulation-parameter-justification.md`](simulation-parameter-justification.md) |
| 4 | 추가 평면도 1~2개로 일반화 검증 | 중간~높음 | 미착수 — Stage 1 파이프라인은 이미 지원 |
| 5 | orphan 모델/로그 정리 또는 코드 복구 | 낮음 | 미착수 — 포함 여부부터 결정 필요 |
| 6 | 코드/데이터 아카이빙 (release + DOI + LICENSE) | 낮음 | 미착수 — 제출 직전에 1회 수행 |

raw 데이터셋은 이 우선순위에 없다 — 화재 대피 도메인에서는 "raw 데이터가 없다"보다
"raw 데이터가 없는 이유를 문헌으로 얼마나 잘 메꿨는가"가 심사 기준이고, 1·3번을
채우면 이 축은 충분히 방어 가능하다.
